## 5. `.env` 配置项汇总（`backend_fastapi/.env`）

| 键 | 含义 | 本地开发 | 生产 |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | DeepSeek 的 Key；不填或为占位值时视为未配置 | 自己的 Key | 必填 |
| `DEEPSEEK_API_BASE` | DeepSeek 地址 | `https://api.deepseek.com` | 同左 |
| `OCR_MODE`（本阶段改了默认值） | `docker`：失败返回 503；`auto`：失败回落示例词并标记降级；`mock`：始终返回示例词 | `auto`，Docker 常开时也可用 `docker` | `docker`（未设置时的默认值） |
| `AI_FALLBACK_ENABLED`（本阶段新增） | AI 失败时是否回落示例故事并标记降级 | `true`，没有 Key 也能跑通流程 | `false`（未设置时的默认值） |
| `OCR_SERVICE_URL` | OCR 容器地址 | `http://localhost:8866` | 部署时再定 |

补充：

- `SERVER_PORT` 只在用 `python main.py` 启动时生效；按约定的 uvicorn 命令使用 `--port 8000`，用不到它。
- `DATABASE_URL` 和 `FRONTEND_URL` 实际上没有生效，见第 8 节第 15 条。
- 如果机器设置了系统代理，后端连本机 OCR 时可能被代理拦截，需要在**启动后端的 shell 里**设置 `NO_PROXY=localhost,127.0.0.1`。这一项不能写进 `.env`：`.env` 里的值只读进 Settings，不会成为进程环境变量，httpx 读不到。

## 6. 旧接口要不要删（待确认项 8）

**审查时的调用方：**

- 前端 `lib/`：没有。
- **`backend_fastapi/static/main.dart.js`**：一份 Flutter Web 构建产物，2026 年 6 月 17 日构建，在 `541c786 first commit` 时提交，之后没有更新过。
  - 其中有 `"/api/v1/story/generate"`（难度写死为 intermediate）和 `"/api/v1/story/fill-blank"` 的调用，搜不到 `learn/compose`。
  - `main.py` 的通配静态路由把它作为 `http://localhost:8000/` 提供出去，即开发者操作文档中"生产构建，同源访问"的方式。
- 文档：`开发者操作文档.md` 中有这两个接口的 curl 示例。

**建议并已决定：继续保留，到第三阶段与静态构建一起处理。** 理由：

1. 现在删除，访问 `localhost:8000/` 的旧网页会在生成这一步报错。那份网页本身已过时（没有确认页、没有降级字段），但仍在被提供出去。
2. 处理这份旧构建需要重新构建或移走 `static/`，会碰到 `main.py` 的静态路由，属于第三阶段 S-1 的范围；`CLAUDE.md` 第 9 节第 10 项也定了 `static/` 本阶段不动。
3. 保留成本很低：已标 `deprecated`，复用同一个 Service，行为和降级处理与新接口一致。

## 8. 整个阶段的清单外发现（都只记录，没改）

**后端**

1. 后端没有日志配置：WARNING / ERROR 只能靠 Python 的兜底处理器输出，不带级别和时间戳；INFO 级别不会输出。（E-4）
2. 提取 JSON 的正则 `\{.*\}` 是贪婪匹配：模型在 JSON 后的说明文字里带 `}` 时提取失败，按解析失败降级，不会 500。（E-4）
3. 上游 HTTP 错误的日志会带上 `DEEPSEEK_API_BASE` 的地址。不是密钥，仅作提醒。（E-4）
4. 系统代理会让 httpx 把"连不上"变成代理返回的 502，原因被归为 `ai_upstream_error` 而不是 `ai_unavailable`。（A-3）
5. OCR 容器返回非 JSON 时，`_docker_ocr` 抛 `ValueError`，后端返回 500。（A-3）
6. `/learn/compose` 的 `words` 没有数量上限，联调中出现过 43 个词的请求。（A-1）
7. 历史搜索没有转义 `%` 和 `_`：输入 `_` 会匹配所有记录。（U-8）
8. 历史搜索只匹配英文短文和单词，不匹配中文翻译。（U-8）
9. 历史接口的 `page_size` 没有上限，`page` 没有校验。（U-8）
10. 历史接口用 OFFSET 分页：删除后第一次"加载更多"只补齐前移进来的几条。行为正确，体验略怪；根治需要后端改为按 id 游标分页。（U-8）

**前端**

11. 历史详情页的填空文字用了 `Scaffold` 外层的 `context`，拿到的是调试模式的错误样式：48 号字、黄色双下划线。（A-1）
12. 历史页加载失败时，错误提示下面仍显示 `No records yet`，容易误解。（U-6）
13. `clearCurrentRecord()` 没有任何调用方：从首页重新拍照时上一轮状态不会被清掉，新照片进入确认页后按钮仍显示 `Regenerate`。（U-8）

**收尾审查新发现**

14. `backend_fastapi/static/` 是第一次提交时的旧网页构建，仍由后端在根路径提供，调用旧接口。（第 6 节）
15. `DATABASE_URL` 和 `FRONTEND_URL` 两个配置项实际没有生效：
    - `models/history.py` 中数据库路径写死，不读 `settings.database_url`
    - CORS 全开，不读 `settings.frontend_url`
    - 在 `.env` 里改这两项不会有效果
16. `README.md` 写的 OCR 是 "PaddleOCR"，实际使用 RapidOCR。之前就存在的问题。

**联调环境的问题（不是产品缺陷）**

17. 在 Windows 的 Git Bash 中，用 curl 的 `-d` 参数直接写中文会因编码问题导致后端返回 400。造数据和手动测试时，把请求体写进 UTF-8 文件后用 `--data-binary` 发送，或改用脚本发送。
