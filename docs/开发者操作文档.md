## 一、概述

拍照 → OCR 提取单词 → 确认页勾选 / 增删单词、选择难度 → 一次请求 `/api/v1/learn/compose` 生成短文、中译与填空 → 保存 / 搜索 / 导出 PDF。所有业务接口都需要登录，数据按用户隔离。

| 层 | 技术 | 位置 |
|---|---|---|
| 客户端 | Flutter 3.41.7（Dart 3.11.5）、Material 3、`provider`、`dio` | `frontend_flutter/` |
| 后端 | FastAPI 0.115 + Uvicorn 0.30，Python 3.13；API → Service → Model 三层 | `backend_fastapi/` |
| 数据库 | MySQL 8.4.11（Docker），SQLAlchemy 2.0 异步 + `asyncmy` 驱动，Alembic 迁移 | `docker/`、`backend_fastapi/alembic/` |
| 账号 | 用户名 + 密码，argon2id 哈希，服务端会话（`sessions` 表） | `backend_fastapi/app/auth/` |
| OCR | RapidOCR（ONNX Runtime）独立容器。目录名仍叫 `paddle_ocr`，是历史遗留 | `docker/paddle_ocr/` |
| AI | DeepSeek `deepseek-chat` | `backend_fastapi/app/services/ai_service.py` |

### 2.1 软件清单

|---|---|---|
| Docker Desktop | 支持 Compose v2 | MySQL、OCR、（可选）后端容器 |
| Python | **3.13**（后端 `venv` 统一用 3.13） | 后端 |

| Chrome | — | Web 调试 |
| Android Studio / 模拟器 | 可选 | Android 调试 |

### 2.2 端口

| 服务 | 端口 | 说明 |
|---|---|---|
| 后端（API + Web 页面） | 8000 | 本地直跑或容器都用 8000 |
| MySQL 8.4 | 主机 **3307** → 容器 3306 | 只绑定 127.0.0.1 |
| OCR | 8866 | 只绑定 127.0.0.1；客户端不直接访问，图片经后端转发 |
| Flutter Web 调试 | 5000 | 固定端口，与 CORS 白名单对应 |

### 2.3 Windows 环境注意事项

- **本机若另装了 MySQL 并占用 3306，不要连接它。** 所有连接都指向 Docker 中的 3307。后端、Alembic、测试、管理员脚本都会拒绝连接本机 3306 或不写端口的地址。
- **系统代理**：有代理时，在**启动后端的那个 shell 里**设置 `$env:NO_PROXY = 'localhost,127.0.0.1'`，写进 `.env` 无效。否则后端访问本机 OCR 会走代理，"连不上"会变成代理返回的 502。
- **Git Bash 中用 curl 发中文**：`-d` 直接写中文会因编码导致 400。把请求体写进 UTF-8 文件，用 `--data-binary @文件` 发送。
- **长路径**：`ui设计/` 下有很长的目录名，克隆到较深的目录时可能超过 260 字符限制。用 `git clone -c core.longpaths=true <地址>`。
- **PowerShell 执行脚本**：`powershell -ExecutionPolicy Bypass -File scripts\build_web.ps1`，不需要改系统执行策略。

## 四、首次搭建

### 4.1 两份 `.env`

| 文件 | 谁读取 | 内容 |
|---|---|---|
| `docker/.env` | docker compose | `MYSQL_ROOT_PASSWORD`、`MYSQL_APP_PASSWORD`、（可选）`MYSQL_APP_USER`、后端容器覆盖项 `BACKEND_*` |
| `backend_fastapi/.env` | 后端（本地直跑和容器都读） | DeepSeek 密钥、数据库连接串、OCR、CORS、限流等全部后端配置 |

```powershell
Copy-Item docker\.env.example docker\.env
Copy-Item backend_fastapi\.env.example backend_fastapi\.env
```

- `.env` 已在 `.gitignore` 中，**不要提交**。
- 两份文件中的应用账号密码必须一致：`docker/.env` 的 `MYSQL_APP_PASSWORD` 就是 `DATABASE_URL` 里 `english_app:` 后面那段。建议只用字母和数字，否则要在连接串中做百分号编码。
- MySQL 密码只在数据卷**首次初始化**时生效。之后要改密码，需要进容器手动 `ALTER USER`。

### 4.2 启动 MySQL 与 OCR

```powershell
cd docker
docker compose up -d mysql paddle_ocr
docker compose ps        # mysql 显示 healthy 后再继续
cd ..
```

首次启动时，`docker/mysql/init/01-create-databases.sh` 会创建：

- 开发库 `english_learning`、测试库 `english_learning_test`（utf8mb4、`utf8mb4_0900_ai_ci`、时区 UTC）
- 应用账号（默认 `english_app`），对两个库有增删改查和建表权限

数据保存在命名卷 `english_learning_mysql_data`。OCR 镜像首次构建需要下载依赖，约几分钟。

### 4.3 后端依赖与迁移

```powershell
cd backend_fastapi
py -3.13 -m venv venv
venv\Scripts\python -m pip install -r requirements-dev.txt     # 含运行时依赖与 pytest
venv\Scripts\python -m alembic upgrade head                    # 开发库
venv\Scripts\python -m alembic current                         # 应显示 0003 (head)
```

测试库不需要手动迁移，pytest 会自动迁移到最新版本。

### 4.4 前端依赖

```powershell
cd frontend_flutter
flutter pub get
```

`flutter pub get` 时会根据 `l10n.yaml` 生成本地化代码。生成的代码已提交进仓库。

## 五、日常启动

### 5.1 本地直跑（日常开发）

```powershell
# 终端 1：容器（已在运行可跳过）
cd docker; docker compose up -d mysql paddle_ocr

# 终端 2：后端
cd backend_fastapi
$env:NO_PROXY = 'localhost,127.0.0.1'
venv\Scripts\python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload --no-proxy-headers

# 终端 3：前端
cd frontend_flutter
flutter run -d chrome --web-port 5000
```

- `--no-proxy-headers`：不信任 `X-Forwarded-For`。uvicorn 默认信任来自 127.0.0.1 的这个头，那样按 IP 的限流就能被伪造请求头绕过。
- Web 调试时，`backend_fastapi/.env` 中设置 `CORS_ALLOW_ORIGINS=http://localhost:5000,http://127.0.0.1:5000`。
- 本地开发建议设置 `OCR_MODE=auto`、`AI_FALLBACK_ENABLED=true`、`API_DOCS_ENABLED=true`（接口文档：`http://localhost:8000/docs`）。

### 5.2 移动端连本地后端

| 场景 | 命令 |
|---|---|
| Android 模拟器 | `flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000` |
| Android 真机（USB） | 先 `adb reverse tcp:8000 tcp:8000`，再 `flutter run`（默认 `http://localhost:8000`） |
| 真机走局域网 | `flutter run --dart-define=API_BASE_URL=http://<电脑的局域网 IP>:8000`；后端要用 `--host 0.0.0.0` 启动 |

明文 HTTP 只在 **debug 构建**中允许（见第十二节）。

### 5.3 验证服务

```powershell
curl.exe http://localhost:8000/health        # {"status":"ok","version":"1.0.0"}
curl.exe http://localhost:8866/health        # {"status":"ok","service":"rapid_ocr"}
curl.exe -i -X POST http://localhost:8000/api/v1/learn/compose    # 未登录：401 {"detail":"请先登录"}
```

带登录的完整示例（Git Bash；用户名和密码换成你自己的测试值）：

```bash
# 注册（返回 token）
printf '{"username":"demo_user","password":"<至少 8 位的测试密码>"}' > /tmp/reg.json
curl -s -X POST http://localhost:8000/api/v1/auth/register \
  -H 'Content-Type: application/json' --data-binary @/tmp/reg.json

# 带凭证调用
TOKEN='<上一步返回的 token>'
printf '{"words":["apple","river"],"difficulty":"beginner"}' > /tmp/compose.json
curl -s -X POST http://localhost:8000/api/v1/learn/compose \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' --data-binary @/tmp/compose.json
```

## 七、数据库与迁移

### 7.1 表

| 表 | 内容 |
|---|---|
| `users` | 用户名（小写，唯一）、argon2id 哈希、是否启用、改密码时间 |
| `sessions` | 凭证的 SHA-256、过期时间、撤销时间；外键级联删除 |
| `learning_records` | 学习记录：`user_id`、单词（JSON）、难度、是否降级、短文 / 中译 / 两份填空、收藏、备注 |
| `rate_limit_counters` | 限流计数：规则 + 主体（用户 ID 或 IP）+ 窗口起点 |

时间列一律 `DATETIME(3)`、存 UTC；接口返回带 `Z` 的 ISO 8601，前端按本地时间显示。完整结构见 [第三阶段收尾审查第 5.1 节](./第三阶段收尾审查.md)。

### 7.2 迁移命令（`backend_fastapi\` 下）

```powershell
venv\Scripts\python -m alembic upgrade head                       # 开发库
venv\Scripts\python -m alembic -x target=test upgrade head        # 测试库
venv\Scripts\python -m alembic current                            # 当前版本
venv\Scripts\python -m alembic history                            # 迁移历史
```

- `-x target=dev|test` 选择目标库，默认 `dev`。`test` 读取 `TEST_DATABASE_URL`，库名必须是 `english_learning_test`。
- **表结构变更只通过迁移**，不手写 DDL。新增迁移的流程：改 `app/models/` → `venv\Scripts\python -m alembic revision --autogenerate -m "说明"` → 人工检查生成的文件（重命名、约束、索引） → 测试库升级、降级各跑一遍 → 跑 pytest → 再执行到开发库。
- 对开发库执行 `downgrade` 会删表或删列，执行前先备份。

### 7.3 备份与恢复

在容器内导出，再复制出来。不要在 PowerShell 中用 `>` 重定向，它可能改变文件编码。

```powershell
# 备份
docker exec english_mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysqldump -uroot --single-transaction --routines --triggers english_learning > /tmp/backup.sql'
docker cp english_mysql:/tmp/backup.sql docker\backup\english_learning-20261010.sql

# 恢复（会覆盖库中同名表，先确认）
docker cp docker\backup\english_learning-20261010.sql english_mysql:/tmp/restore.sql
docker exec english_mysql sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" mysql -uroot english_learning < /tmp/restore.sql'
```

`docker/backup/` 已在 `.gitignore` 中。上线后需要每日备份、保留 7 天，并演练恢复。

## 八、账号体系

### 8.1 规则

| 项 | 规则 |
|---|---|
| 用户名 | 3–20 位字母、数字、下划线；不区分大小写（统一存小写） |
| 密码 | 8–128 位；不能与用户名相同；不能是常见弱密码；不强制字母加数字 |
| 哈希 | argon2id（`argon2-cffi` 默认参数），在线程池中计算 |
| 凭证 | 32 字节随机数，只通过 `Authorization: Bearer <token>` 传递；库中只存 SHA-256 |
| 有效期 | 登录时起 30 天，不随使用顺延 |
| 失效 | 登出：当前凭证立即失效；修改密码：**所有**旧凭证失效，返回新凭证；停用账号：全部失效 |
| 登录失败 | 用户不存在、密码错误、用户名格式不合法：结果完全相同（401"用户名或密码错误"）；用户不存在时也做一次哈希 |
| 越权 | 访问别人的记录与访问不存在的记录结果相同（404） |
| 找回密码 | 没有自助找回；登录页提示"忘记密码？请联系管理员重置。" |

鉴权只在一处：`app/auth/dependencies.py` 的 `get_current_user`。除 `/health`、注册、登录和静态页面外，所有接口都依赖它；`tests/unit/test_auth_rules.py` 会检查新增接口是否漏加。新增接口时挂在已有的路由组上即可。

### 8.2 前端

- `AuthProvider` 管理登录状态：启动时用本地凭证调 `/auth/me` 恢复登录；网络失败时显示启动失败页（重试 / 退出登录）。
- 凭证存储：移动端 `flutter_secure_storage`；Web 端 `sessionStorage`（关闭标签页即需重新登录）。Android 关闭了自动备份（`allowBackup="false"`）。
- Dio 拦截器统一附加凭证。收到当前凭证的 401 时清空凭证和全部用户状态（`AppProvider.resetForSignOut()`），回到登录页并提示"登录已失效，请重新登录。"。多个并发请求同时 401 只处理一次。

### 8.3 管理员脚本（`backend_fastapi\` 下）

```powershell
venv\Scripts\python -m scripts.admin list-users                       # 只读
venv\Scripts\python -m scripts.admin reset-password <用户名>           # 新密码用 getpass 输入两次
venv\Scripts\python -m scripts.admin disable <用户名>
venv\Scripts\python -m scripts.admin enable <用户名>
venv\Scripts\python -m scripts.admin cleanup-sessions [--dry-run]
venv\Scripts\python -m scripts.admin cleanup-rate-limits [--dry-run]
venv\Scripts\python -m scripts.admin --target test list-users         # 操作测试库
```

防误操作：执行前打印目标库（主机:端口/库名，不含密码）和用户当前状态；写操作必须再输入一次用户名确认，没有跳过确认的参数；重置密码和停用账号会让该用户的全部会话失效；每个写操作在一个事务里完成。

## 九、限流与输入上限

### 9.1 限流

| 规则 | 维度 | 默认额度 | 接口 | 配置项 |
|---|---|---|---|---|
| ocr | 用户 | 60 次 / 天 | `POST /api/v1/ocr/recognize` | `RATE_LIMIT_OCR_PER_USER`、`RATE_LIMIT_OCR_WINDOW_SECONDS` |
| compose | 用户 | 30 次 / 天 | `POST /api/v1/learn/compose` | `RATE_LIMIT_COMPOSE_PER_USER`、`RATE_LIMIT_COMPOSE_WINDOW_SECONDS` |
| login | IP | 10 次 / 10 分钟 | `POST /api/v1/auth/login` | `RATE_LIMIT_LOGIN_PER_IP`、`RATE_LIMIT_LOGIN_WINDOW_SECONDS` |
| register | IP | 5 次 / 小时 | `POST /api/v1/auth/register` | `RATE_LIMIT_REGISTER_PER_IP`、`RATE_LIMIT_REGISTER_WINDOW_SECONDS` |
| change_password | 用户 | 10 次 / 小时 | `POST /api/v1/auth/change-password` | `RATE_LIMIT_CHANGE_PASSWORD_PER_USER`、`RATE_LIMIT_CHANGE_PASSWORD_WINDOW_SECONDS` |

- 计数存在 `rate_limit_counters` 表中，原子自增，UTC 固定窗口（窗口最长 1 天）。**按天的额度在 UTC 0 点（北京时间 8 点）重置。**
- 计入规则：通过鉴权的每次请求都计入，包括失败、降级和 422；未登录（401）和请求体超限（413）不计入。登录、注册、修改密码每次都计入，包括成功的。
- 超限返回 **429**，带 `Retry-After` 响应头和中文 `detail`（如"生成次数已用完（每天 30 次），请约 3 小时后再试"）。前端直接显示 `detail`，不显示"重试"按钮。
- 过期计数保留 2 天后，由每日维护任务清理。
- **客户端 IP 只取连接地址**，不信任 `X-Forwarded-For`。部署到反向代理后面时必须改配置，否则所有人共用一个登录 / 注册额度：代理用连接地址覆盖该头（Nginx：`proxy_set_header X-Forwarded-For $remote_addr;`），后端改为 `--proxy-headers --forwarded-allow-ips=<代理地址>`。

### 9.2 输入上限

| 项 | 上限 | 超出 |
|---|---|---|
| 生成 / 保存的单词数 | 20 个 | 422"一次最多 20 个单词" |
| 单个单词长度 | 40 字符 | 422 |
| `/ocr/recognize` 请求体 | 10 MB | 413（先于鉴权判断） |
| 其他 `/api/` 请求体 | 1 MB | 413 |
| 历史 `page` / `page_size` / `search` | 1–10000 / 1–50 / 100 字符 | 422 |
| 保存记录的文本字段 / 备注 | 16000 / 2000 字符 | 422 |

前端在确认页同样限制 20 个单词和 40 个字符。

## 十、接口概览

统一前缀 `/api/v1`，错误响应为 `{"detail": "中文文案"}`。详细的请求、响应和错误码见 [后端接口清单](./后端接口清单.md)。

| 方法 | 路径 | 需登录 | 说明 |
|---|---|---|---|
| GET | `/health` | 否 | 健康检查（不访问数据库） |
| POST | `/auth/register` | 否 | 注册即登录，返回 `token` |
| POST | `/auth/login` | 否 | 登录，返回 `token` |
| POST | `/auth/logout` | 是 | 让当前凭证失效（204） |
| GET | `/auth/me` | 是 | 当前用户 |
| POST | `/auth/change-password` | 是 | 修改密码，返回新 `token` |
| POST | `/ocr/recognize` | 是 | `multipart/form-data` 的 `file` → `{words, degraded, reason}` |
| POST | `/learn/compose` | 是 | `{words, difficulty}` → 短文、中译、两份填空、`degraded`、`reason` |
| POST | `/history/save` | 是 | 保存当前记录 |
| GET | `/history/records` | 是 | 分页 + 搜索（单词与英文短文，`%` `_` 按字面匹配） |
| GET / PUT / DELETE | `/history/records/{id}` | 是 | 详情 / 更新收藏与备注 / 删除；别人的记录返回 404 |
| GET | `/{任意路径}` | 否 | 静态网页（`backend_fastapi/static/`），找不到时回落 `index.html` |

**降级**：`OCR_MODE=auto|mock` 或 `AI_FALLBACK_ENABLED=true` 时，失败会返回示例数据并带 `degraded: true` 和 `reason`，前端显示降级提示条。生产配置下失败直接返回 502 / 503 / 504。

## 十二、构建与部署

### 12.1 Web：构建并由后端托管

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_web.ps1
# 前后端不同源时：
powershell -ExecutionPolicy Bypass -File scripts\build_web.ps1 -ApiBaseUrl https://api.example.com
```

脚本执行：`flutter pub get` → `flutter build web --release --no-web-resources-cdn --dart-define=API_BASE_URL=<参数，默认空串>` → 清空 `backend_fastapi/static/` 后复制 `frontend_flutter/build/web/` 的内容。

- `API_BASE_URL` 为空时请求走相对路径 `/api/v1/...`，无论用 `localhost`、局域网 IP 还是正式域名打开都能用，不涉及 CORS。
- `--no-web-resources-cdn`：CanvasKit 从产物自带的 `canvaskit/` 加载，不访问 Google CDN（国内可能打不开）。
- `static/` 不入版本库，干净克隆后需要先运行脚本。没有 `index.html` 时，后端根路径返回 `{"message": "AI English Learning API"}`。
- 浏览器中残留旧构建的 service worker 时，更新后可能看到旧页面，强制刷新即可。

### 12.2 Docker 完整部署

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_web.ps1     # 镜像直接复制 static/，先构建 Web
cd docker
docker compose up -d --build
docker compose ps
docker compose logs -f backend
```

| 项 | 说明 |
|---|---|
| 镜像 | `python:3.13.4-slim-bookworm` 两阶段构建；以 UID 10001 的非 root 用户运行 |
| 镜像内容 | `.dockerignore` 白名单：只有 `main.py`、`app/`、`alembic/`、`scripts/`、`static/` 等运行所需文件；`.env`、`data/`、测试不进镜像 |
| 配置 | `env_file: ../backend_fastapi/.env`（运行时注入）；compose 覆盖 `DATABASE_URL`（服务名 `mysql:3306`）、`OCR_SERVICE_URL`（`paddle_ocr:8866`）、`OCR_MODE=docker`、`AI_FALLBACK_ENABLED=false`、`API_DOCS_ENABLED=false`、`DEBUG=false` |
| 启动 | 等 MySQL 健康检查通过 → `alembic upgrade head` → uvicorn（1 个 worker，`--no-proxy-headers`）；迁移失败时容器退出 |
| 健康检查 | 容器内访问 `/health` |
| 日志 | 统一格式、UTC 时间戳，输出到标准输出；登录失败、触发限流记 WARNING（不含密码与凭证） |
| 数据 | 命名卷 `english_learning_mysql_data`，`down` 后再 `up` 数据仍在；`docker compose down -v` 会**删除数据**，不要随意执行 |
| 端口 | 后端 `8000:8000` 绑定所有网卡（方便局域网真机调试）；上线时改为 `127.0.0.1:8000:8000`，由反向代理转发 |

只更新后端代码或 Web 产物时：`docker compose up -d --build backend`。

### 12.3 移动端构建

```powershell
cd frontend_flutter
flutter build apk --release --dart-define=API_BASE_URL=https://<正式域名>
flutter build ios --release --dart-define=API_BASE_URL=https://<正式域名>     # 需要 macOS
```

## 十四、常见问题

| 现象 | 原因与处理 |
|---|---|
| 所有接口返回 401"请先登录" | 没带 `Authorization: Bearer <token>`；App 中重新登录 |
| 401"登录已失效，请重新登录" | 凭证过期、已登出、已改密码或账号被停用 |
| 429 "…次数已用完…" | 触发限流，按 `Retry-After` 等待；本地调试可在 `.env` 中调大 `RATE_LIMIT_*` 或设 `RATE_LIMIT_ENABLED=false`（不要用于生产） |
| 413 | 图片超过 10 MB 或请求体超过 1 MB |
| 422"一次最多 20 个单词" | 单词超过 `COMPOSE_MAX_WORDS` |
| 浏览器控制台报 CORS 错误 | `flutter run -d chrome` 没有固定 `--web-port 5000`，或 `CORS_ALLOW_ORIGINS` 没有包含当前来源；由后端托管的页面是同源的，不会有这个问题 |
| 识别返回 503"识别服务暂时不可用" | OCR 容器没在运行（`docker compose ps`）；或有系统代理但没设置 `NO_PROXY` |
| 生成返回 502 / 503 / 504 | DeepSeek 出错 / 未配置 / 超时。本地开发可以打开 `AI_FALLBACK_ENABLED=true` |
| 后端启动或请求时报"refusing to connect to 127.0.0.1:3306" | `DATABASE_URL` 指向了本机 3306 或没写端口，改为 3307 |
| pytest 报 `unsafe TEST_DATABASE_URL` 并退出 | 测试库连接串的库名不是 `english_learning_test`，或指向本机 3306 |
| MySQL 容器一直不 healthy | `docker compose logs mysql`；首次初始化较慢；`docker/.env` 缺少密码时初始化脚本会报错退出 |
| 改了 `docker/.env` 的 MySQL 密码但登录失败 | 密码只在数据卷首次初始化时生效，需要进容器 `ALTER USER` |
| 后端托管的页面还是旧版本 | 没有重新运行 `scripts\build_web.ps1`，或浏览器缓存了旧 service worker（强制刷新）；容器部署还需要 `docker compose up -d --build backend` |
| 根路径返回 `{"message": "AI English Learning API"}` | `backend_fastapi/static/` 中没有 Web 构建产物，先运行构建脚本 |
| Git Bash 中 curl 发中文得到 400 | 用 `--data-binary @文件` 发送 UTF-8 文件 |
| 克隆时报 "Filename too long" | `git clone -c core.longpaths=true` |

## 十五、上线前清单

代码层面已具备对外开放的条件，但**完成以下事项之前不能上线**，尤其是 HTTPS：有了账号体系后，密码和登录凭证走明文 HTTP 等于公开。

- HTTPS：域名、反向代理（Nginx / Caddy）、证书；服务器在中国大陆的需要 ICP 备案
- 反向代理传递客户端 IP（第 9.1 节）；反向代理的请求体上限不小于 10 MB
- 后端端口只绑定本机；服务器防火墙只开放 80 / 443
- 生产配置：`OCR_MODE=docker`、`AI_FALLBACK_ENABLED=false`、`API_DOCS_ENABLED=false`
- 移动端 release 构建使用 `https://` 的 `API_BASE_URL`
- MySQL：迁移账号与运行账号分开（运行账号只要增删改查权限），端口不对公网开放；每日备份并演练恢复
- DeepSeek 后台设置消费上限
- 替换授权不明的插画；隐私政策、用户协议、注销账号；iOS 权限说明

每一项的当前状态见 [第三阶段收尾审查第 10 节](./第三阶段收尾审查.md)。
