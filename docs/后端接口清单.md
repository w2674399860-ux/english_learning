# 后端接口清单

> 依据代码现状整理：第三阶段完成（2026-10-10）。第一段结束时（2026-10-07）初稿，第三阶段收尾时按最终代码核对更新。
> 以代码为准：`backend_fastapi/app/api/`、`app/auth/`、`app/ratelimit/`、`app/core/body_limit.py`。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| 前缀 | 业务接口都在 `/api/v1` 下 |
| 凭证 | 登录、注册返回 `token`；之后每个请求带请求头 `Authorization: Bearer <token>`。**不接受** URL 查询参数或 Cookie |
| 凭证有效期 | 登录时起 30 天（`SESSION_TTL_DAYS`），不随使用顺延；登出、改密码、账号被停用后立即失效 |
| 时间 | 一律 UTC，ISO 8601 带 `Z`，精确到毫秒，如 `2026-10-07T03:47:00.123Z`；前端显示时转本地时间 |
| 错误响应 | `{"detail": ...}`。`detail` 多数是**中文字符串**，可直接展示；FastAPI 参数校验失败时 `detail` 是**数组**（见第 4 节），前端不应直接展示 |
| 跨域 | 只放行 `CORS_ALLOW_ORIGINS` 白名单（默认空）。允许方法 `GET POST PUT DELETE`，允许请求头 `Authorization`、`Content-Type`，暴露 `Retry-After` |
| 请求体大小 | `/api/v1/ocr/recognize` 整个请求体 ≤ 10 MB，其他 `/api/` 接口 ≤ 1 MB；超限 413，**先于鉴权**判断 |

### 所有需登录接口共有的错误

| 状态码 | detail | 场景 |
|---|---|---|
| 401 | `请先登录` | 没带 `Authorization` 头 |
| 401 | `登录已失效，请重新登录` | 凭证无效、过期、已登出、已改密码、账号已停用 |

401 响应带 `WWW-Authenticate: Bearer`。前端收到当前凭证的 401 时清空本地凭证与用户状态，回到登录页（并发的多个 401 只处理一次）。

### 限流（S-5）

| 规则 | 维度 | 默认额度 | 作用接口 |
|---|---|---|---|
| ocr | 用户 | 60 次 / 天 | `POST /api/v1/ocr/recognize` |
| compose | 用户 | 30 次 / 天 | `POST /api/v1/learn/compose` |
| login | IP | 10 次 / 10 分钟 | `POST /api/v1/auth/login` |
| register | IP | 5 次 / 小时 | `POST /api/v1/auth/register` |
| change_password | 用户 | 10 次 / 小时 | `POST /api/v1/auth/change-password` |

- 窗口按 UTC 对齐：**按天的额度在 UTC 0 点（北京时间 8 点）重置**
- 计入规则：通过鉴权的每次请求都计入，包括失败（502/503/504）、降级、参数错误（422）；未登录（401）与 413 不计入。登录、注册、修改密码每次请求都计入（含成功）
- 超限：**429**，带 `Retry-After: <秒>` 响应头，`detail` 示例：
  - `识别次数已用完（每天 60 次），请约 3 小时后再试`
  - `生成次数已用完（每天 30 次），请约 3 小时后再试`
  - `登录尝试过于频繁（每 10 分钟 10 次），请 8 分钟后再试`
  - `注册过于频繁（每小时 5 次），请 40 分钟后再试`
  - `修改密码尝试过于频繁（每小时 10 次），请 40 分钟后再试`
- 已超限时，即使请求参数有误也返回 429（限流先于参数校验）
- 前端：识别、生成的 429 不显示"重试"按钮，直接展示 `detail`；登录、注册、修改密码的 429 按 `Retry-After` 在提交按钮上倒计时

## 3. 各接口详情

### 账号

#### POST `/api/v1/auth/register`

请求：`{"username": "Alice_01", "password": "<至少 8 位的密码>"}`

响应 201：

```json
{
  "token": "<43 个字符>",
  "token_type": "bearer",
  "expires_at": "2026-11-06T03:47:00.123Z",
  "user": {"id": 1, "username": "alice_01", "created_at": "2026-10-07T03:47:00.123Z"}
}
```

注册即登录。用户名统一存小写。

| 状态码 | detail |
|---|---|
| 409 | `用户名已被注册`（不区分大小写） |
| 422 | `用户名需为 3–20 位字母、数字或下划线` |
| 422 | `密码至少 8 位` / `密码不能超过 128 位` / `密码不能与用户名相同` / `密码过于简单，请换一个` |
| 422 | 数组（字段缺失、类型错误、用户名超过 64 字符、密码超过 1024 字符） |
| 413 | `请求内容过大` |
| 429 | 见限流 |

前端校验规则（与后端一致，`app/auth/passwords.py`）：用户名 `^[A-Za-z0-9_]{3,20}$`；密码 8~128 位、不等于用户名（不区分大小写）、不在常见弱密码表中（弱密码表只在后端判断）。

#### POST `/api/v1/auth/login`

请求：`{"username": "alice_01", "password": "..."}`（用户名不区分大小写）

响应 200：同注册。

| 状态码 | detail |
|---|---|
| 401 | `用户名或密码错误`（用户不存在、密码错误、用户名格式不合法，三种情况完全相同） |
| 403 | `账号已停用，请联系管理员`（仅在密码正确时返回） |
| 422 | 数组（字段缺失或类型错误） |
| 413、429 | 见上 |

登录页提示："忘记密码请联系管理员"（没有自助找回）。

#### POST `/api/v1/auth/logout`

无请求体。响应 **204**（无响应体）。只让当前凭证失效，其他设备的登录不受影响。

#### GET `/api/v1/auth/me`

响应 200：`{"id": 1, "username": "alice_01", "created_at": "..."}`。启动时用它判断本地凭证是否仍有效。

#### POST `/api/v1/auth/change-password`

请求：`{"old_password": "...", "new_password": "..."}`

响应 200：`{"token": "<新凭证>", "token_type": "bearer", "expires_at": "..."}`

**改密码后所有旧凭证（包括当前这个）立即失效**，前端必须用响应中的新 `token` 替换本地凭证。

| 状态码 | detail |
|---|---|
| 400 | `当前密码不正确`（当前凭证不受影响） |
| 422 | 与注册相同的密码规则文案；`新密码不能与当前密码相同`；数组 |
| 429 | 见限流（超限后不再校验原密码） |

### 识别与生成

#### POST `/api/v1/ocr/recognize`

`multipart/form-data`，字段 `file`，`Content-Type` 必须是 `image/*`。

响应 200：`{"words": ["apple", "book"], "degraded": false, "reason": null}`

- `degraded=true` 时 `reason` 为 `ocr_mock`（mock 模式）或 `ocr_unavailable`（auto 模式下 OCR 不可用，返回示例词）

| 状态码 | detail |
|---|---|
| 400 | `只能上传图片文件` |
| 413 | `图片不能超过 10 MB`（按整个请求体计算，含 multipart 开销约几百字节） |
| 422 | 数组（缺少 `file`） |
| 429 | 见限流 |
| 503 | `识别服务暂时不可用，请稍后再试` |

#### POST `/api/v1/learn/compose`

请求：`{"words": ["cat", "book"], "difficulty": "intermediate"}`，`difficulty` 取 `beginner` / `intermediate` / `advanced`，默认 `intermediate`。

响应 200：

```json
{"english": "...", "chinese": "...", "english_blank": "...", "chinese_blank": "...", "degraded": false, "reason": null}
```

- `degraded=true` 时（仅 `AI_FALLBACK_ENABLED=true`）`reason` 为 `ai_not_configured` / `ai_unavailable` / `ai_timeout` / `ai_upstream_error` / `ai_parse_failed`，内容为示例故事
- 生成可能较慢：后端单次调用 DeepSeek 超时 60 秒；前端 `receiveTimeout` 180 秒

| 状态码 | detail |
|---|---|
| 400 | `请至少选择一个单词` |
| 422 | `一次最多 20 个单词` |
| 422 | `单词不能超过 40 个字符：<前 20 个字符>…` |
| 422 | 数组（`difficulty` 非法、`words` 不是字符串数组） |
| 413 | `请求内容过大` |
| 429 | 见限流 |
| 502 | `生成服务出错，请稍后再试` / `生成结果有误，请重试` |
| 503 | `生成服务未配置，请联系管理员` / `生成服务暂时不可用，请稍后再试` |
| 504 | `生成超时，请重试` |


### 历史记录（只能访问自己的记录）

访问他人的记录与访问不存在的记录**结果完全相同**（404），前端无需区分。

#### POST `/api/v1/history/save`

请求：

```json
{
  "image_url": "a.png",
  "words": ["cat"],
  "english_story": "...", "chinese_translation": "...",
  "english_blank": "...", "chinese_blank": "...",
  "difficulty": "intermediate",
  "is_degraded": false
}
```

`difficulty`、`is_degraded` 可选，默认 `intermediate`、`false`；前端保存时两者都会发送。`image_url` 实际只存文件名。

响应 200：`{"id": 12, "message": "已保存"}`

| 状态码 | detail |
|---|---|
| 422 | `一次最多 20 个单词` / `单词不能超过 40 个字符：…` |
| 422 | 数组：`image_url` 超过 255 字符；`english_story`、`chinese_translation`、`english_blank`、`chinese_blank` 任一超过 16000 字符；缺字段或类型错误 |
| 413 | `请求内容过大` |

#### GET `/api/v1/history/records?page=1&page_size=20&search=`

| 参数 | 范围 | 超出 |
|---|---|---|
| `page` | 1~10000 | 422 |
| `page_size` | 1~50（`HISTORY_MAX_PAGE_SIZE`） | 422 |
| `search` | ≤ 100 字符；匹配短文与单词，`%` `_` 按字面匹配，不区分大小写 | 422 |

响应 200：`{"records": [Record, ...], "total": 35, "page": 1, "page_size": 20}`，按创建时间倒序。

Record：

```json
{
  "id": 12, "image_url": "a.png", "words": ["cat"],
  "difficulty": "intermediate", "is_degraded": false,
  "english_story": "...", "chinese_translation": "...", "english_blank": "...", "chinese_blank": "...",
  "is_favorite": 0, "notes": null,
  "created_at": "2026-10-07T03:47:00.123Z", "updated_at": "2026-10-07T03:47:00.123Z"
}
```

兼容层（尚未清理）：字段名仍叫 `image_url`（数据库列为 `image_name`）；`is_favorite` 为整数 0 / 1。前端读取时同时兼容 0 / 1 与布尔值；改为 `image_name` 与布尔值需要前后端同时修改。

#### GET `/api/v1/history/records/{record_id}`

响应 200：Record。404 `记录不存在`；`record_id` 不是整数时 422。

#### PUT `/api/v1/history/records/{record_id}`

请求：`{"is_favorite": true}` 或 `{"notes": "..."}`（两者可同时给）。响应 200：`{"message": "已更新"}`。

404 `记录不存在`：记录不存在或不属于自己；**两个字段都不给时也返回 404**（现有行为）。`notes` 最多 2000 字符，超出 422（数组）。

#### DELETE `/api/v1/history/records/{record_id}`

响应 200：`{"message": "已删除"}`；404 `记录不存在`。

## 4. 参数校验错误（422 数组）的结构

```json
{"detail": [{"type": "string_type", "loc": ["body", "password"], "msg": "Input should be a valid string"}]}
```

- 每项只有 `type`、`loc`、`msg`；**不回显请求中的原值**（FastAPI 默认的 `input`、`ctx` 已去掉，避免回显密码）
- `msg` 是英文。前端遇到数组形式的 `detail` 时显示通用文案（"请求参数有误。"）；需要定位字段时看 `loc` 最后一项

## 5. 仍为英文的文案

只剩 422 数组中的 `msg`（FastAPI / Pydantic 生成，前端不直接展示，统一显示"请求参数有误。"）。其余 `detail` 已在 U-10 改为中文。
